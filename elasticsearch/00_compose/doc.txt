### **🚀 Fix `vm.max_map_count` Too Low for Elasticsearch in Docker**  
Elasticsearch requires `vm.max_map_count` to be **at least 262144**.  

---

## **✅ Solution 1: Increase `vm.max_map_count` on Host Machine (Linux)**  
Run the following command on your **host system** (not inside the container):  
```sh
sudo sysctl -w vm.max_map_count=262144
```
This change is **temporary** and resets after a reboot.

### **📌 Make It Permanent**
1. Edit the system configuration file:  
   ```sh
   sudo nano /etc/sysctl.conf
   ```
2. Add this line at the bottom:  
   ```
   vm.max_map_count=262144
   ```
3. Apply the changes:  
   ```sh
   sudo sysctl -p
   ```

---

## **✅ Solution 2: Apply the Fix in Docker Compose**  
If using **Docker Compose**, add the following under the `elasticsearch` service:

```yaml
version: "3.8"
services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.17.2
    container_name: es01
    environment:
      - discovery.type=single-node
    ports:
      - "9200:9200"
    ulimits:
      memlock: -1
    deploy:
      resources:
        limits:
          memory: 4g
    sysctls:
      - vm.max_map_count=262144
```

Then restart Elasticsearch:
```sh
docker-compose up -d --force-recreate
```

---

## **✅ Solution 3: Run with `--sysctl` in `docker run`**
If running Elasticsearch with `docker run`, use:
```sh
docker run --name es01 --net elastic -p 9200:9200 -it --ulimit memlock=-1 \
  --sysctl vm.max_map_count=262144 \
  -m 4GB docker.elastic.co/elasticsearch/elasticsearch:8.17.2
```
